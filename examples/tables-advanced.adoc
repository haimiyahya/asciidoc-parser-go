== Table Attributes and Styling

=== Frame Control

The frame attribute controls which sides of the table have borders.

[frame="all"]
.Frame All (default)
|===
| Cell 1 | Cell 2
| Cell 3 | Cell 4
|===

[frame="topbot"]
.Frame Top and Bottom Only
|===
| Cell 1 | Cell 2
| Cell 3 | Cell 4
|===

[frame="sides"]
.Frame Sides Only
|===
| Cell 1 | Cell 2
| Cell 3 | Cell 4
|===

[frame="none"]
.Frame None (grid still shows internal borders)
|===
| Cell 1 | Cell 2
| Cell 3 | Cell 4
|===

[frame="none",grid="none"]
.Completely Borderless (frame + grid none)
|===

| Cell 3 | Cell 4
|===

== Best Practices

=== When to Use Tables

Tables are ideal for:

* *Tabular data* - Information that naturally fits in a grid
* *Comparisons* - Side-by-side feature or price comparisons
* *Reference material* - Command options, configuration keys, APIs
* *Specifications* - Technical details with consistent structure

Avoid tables for:
* Simple lists (use unordered or ordered lists instead)
* Layout purposes (tables should convey semantic data relationships)

=== Table Design Guidelines

.Guidelines for Effective Tables
[cols="2*",options="header"]
|===
| Practice | Recommendation
| Headers | Always use `options="header"` for data tables
| Alignment | Left-align text, right-align numbers
| Widths | Use `cols="*"` for equal or `cols="<,>,^"` for alignment
| Captions | Provide captions for context and accessibility
| Stripes | Use `stripes="even"` for wide tables to aid readability
| Frames | Use `frame="all"` for standalone, `frame="topbot"` for inline
|===

=== Accessibility Considerations

When creating tables, consider:

. *Always provide headers* using `options="header"`
. *Use descriptive captions* to explain table purpose
. *Keep tables simple* - avoid excessive nesting
. *Specify column widths* for predictable rendering
. *Use appropriate alignment* for data types

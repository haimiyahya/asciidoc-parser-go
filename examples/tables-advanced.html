Best Practices

When to Use Tables

Tables are ideal for:

  • Tabular data - Information that naturally fits in a grid

  • Comparisons - Side-by-side feature or price comparisons

  • Reference material - Command options, configuration keys, APIs

  • Specifications - Technical details with consistent structure

Avoid tables for:

  • Simple lists (use unordered or ordered lists instead)

  • Layout purposes (tables should convey semantic data relationships)

Table Design Guidelines

Guidelines for Effective Tables

Practice

Recommendation

Headers

Always use options="header" for data tables

Alignment

Left-align text, right-align numbers

Widths

Use cols="*" for equal or cols="<,>,^" for alignment

Captions

Provide captions for context and accessibility

Stripes

Use stripes="even" for wide tables to aid readability

Frames

Use frame="all" for standalone, frame="topbot" for inline

Accessibility Considerations

When creating tables, consider:

  1. Always provide headers using options="header"

  2. Use descriptive captions to explain table purpose

  3. Keep tables simple - avoid excessive nesting

  4. Specify column widths for predictable rendering

  5. Use appropriate alignment for data types
